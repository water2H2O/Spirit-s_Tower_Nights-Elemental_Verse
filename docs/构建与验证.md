### ⚠️ 接入新素材包：务必用脚本，不要手动覆盖

```cmd
python tools\integrate-textures.py "<素材包.zip>" v8
```

**为什么不能用"复制粘贴"**：素材包里也带 `models\item\element_vial.json` 这类文件，
直接覆盖会连我们生成的 `overrides` 分发段一起盖掉 ——
表现是**所有元素瓶图标变成一个**，而且日志里没有任何报错。
（踩过一次，只能靠眼睛发现。）

脚本会按正确顺序做四件事：复制资源 → 把作者的载体模型落成 `<载体>_base.json`
→ 重新生成分发模型 → 归档整包。

`static-check.py` 里也加了对应检查：分发项与枚举不一致时会直接报错并提示重跑生成器。

我这边的环境事实（已实测确认）：

结论：**依赖下载不了、Gradle 缓存建不了 → 我在这里无法编译。**
但 JDK 有、工作区可写 → **你那边只要网络通，就能一条命令编译。**

## 三、失败了贴什么给我

### 编译失败（`dev.cmd build` 报错）

贴**最后 30 行左右**就够，重点是这几行：

```
> Task :compileJava FAILED
错误: 找不到符号
  symbol:   method xxxx
  location: class yyyy
```

**贴的时候要包含文件名和行号**（`SpiritsTowerNightsElementalVerse.java:57`）。
Java 的报错是**第一个错误最有用**，后面往往是连锁反应 ——
如果一次报了 20 个错，先只贴**第一个**。

### 游戏启动失败

日志在：

```
run\logs\latest.log          ← 最新一次
run\crash-reports\           ← 崩溃报告
```

贴 `latest.log` 里**含 `elemental_verse` 的那几行**，以及第一个
`Caused by:` 后面的堆栈。整个文件通常太长，不用全贴。

### 游戏起来了但东西不对

直接说现象 + 截图。比如"元素放到箱子里十分钟了还是亮的"，
比"衰变没生效"有用得多。

## 四、按阶段的验收清单

**每个阶段结束时，我会给你一份针对那一阶段的逐条清单**
（放在 `docs/分阶段/NN-xxx.md` 的「验收标准」一节里），照着点即可。

清单的写法是"**能判定通过/不通过**"的句子，例如：

> ☐ 把地元素放普通箱子，用指令把时间推快，它变成砂、再变成死寂土

而不是"衰变系统工作正常"这种没法验的话。

### 推进游戏时间的指令

调衰变基本都要推时间：

```
/time add 24000          → 加 1 游戏日
/time add 240000         → 加 10 游戏日
/time set day            → 调回白天
```

常用辅助：

```
/gamemode creative
/give @s elemental_verse:earth_element 64
```

## 五、CI 怎么用

`.github/workflows/build.yml` 每次 push 自动编译。

- **编译报错**：仓库 → Actions → 点那次运行 → 展开 `Build with Gradle` 步骤看日志
- **要 jar**：同一次运行页面底部的 **Artifacts** 里下载

我这边能读 CI 的结果，所以 **push 之后编译问题通常我能自己发现并修**，
不需要你来读日志。你主要负责的是**进游戏实测手感** —— 那个只有你能做。

## 六、推送这一步得你自己敲

我这边的环境事实：**SSH 走不通**（沙箱不允许 Git 的 `ssh.exe` 建管道，
报 `couldn't create signal pipe, Win32 error 5`），**HTTPS 也不通**
（TLS 拿不到凭证 `SEC_E_NO_CREDENTIALS`）。所以 `git push` 只能你在自己的终端做：

```cmd
cd D:\vibe_coding\elemental-verse
git push -u origin main
```

之后**每次我改完代码**，也都是这一条。你机器上的 `.ssh` 里 `id_rsa` 是好的，
普通终端里能推上去。

**推上去之后**：仓库的 **Actions** 页面会自动跑一次编译（`.github/workflows/build.yml`）。
编译失败的话我能读那份日志，就能自己发现问题、自己修 —— 这是 CI 那一半的用处。

## 八、游戏启动闪退（点了没反应）怎么修

**症状**：双击启动，窗口一闪就没了；`latest.log` 停在

```
Loading ImmediateWindowProvider fmlearlywindow
```

**没有任何异常栈** —— 因为崩在原生层（LWJGL），不是 mod 的问题。

**原因**：PCL 启动时会把 `libraries` 里的 `*-natives-windows.jar` 解压进
`<版本>-natives\` 目录，但这台机器上**这一步反复只解出 1 个 DLL**
（只有 `lwjgl.dll`，缺 `glfw/opengl/freetype/openal/...`）。
缺 `lwjgl_opengl.dll` 就必然在创建 GL 上下文时死掉，正好是日志断掉的那一行。

**修**：双击运行（或用命令行）

```cmd
tools\fix-game-natives.cmd
```

它会把 8 个 DLL 从 `libraries` 里重新解压回去，跑完提示 `[OK]` 就能启动游戏。
可反复执行，不会破坏别的东西。

**如果反复出现**：多半是杀毒软件把解压出来的 DLL 删掉了。
把下面这个目录加进杀软白名单：

```
D:\vibe_coding\mod\versions\1.21.1-NeoForge_21.1.262\1.21.1-NeoForge_21.1.262-natives\
```

> 注意：`dev.cmd runClient` **不受这个影响** —— 开发环境用的是 Gradle 自己的
> natives 处理方式。所以本地开发能跑、PCL 启动闪退，是这个原因，不是代码问题。
