## 一、为什么这三个必须一起做

它们是一条**依赖链**，单独做任何一个都会变成摆设：

```
基础仪式台  ──产出──▶  符文版  ──装进──▶  符文柜
（把元素变成东西）      （一张"配方/指令"）    （靠符文维持的仓储）
```

- 没有仪式台，符文版无处生产
- 没有符文版，符文柜只是个贵箱子
- 没有符文柜，玩家在中期就得一直被"衰变"追着跑

**这三件做完，模组才第一次有"技术升级"的感觉** —— 从"捡元素"变成"经营元素"。

## 二、基础仪式台

### 2.1 形态

**单方块**（不做多方块结构）。理由：

- 多方块结构要处理校验、破坏、跨区块，投入产出比很低
- 单方块 + 图形化界面已经能表达"仪式"，参考原版酿造台/附魔台的复杂度足够

外观用**石质基座 + 中央凹槽 + 四个角落的元素卡槽**，界面 3×3 输入 + 1 输出。

### 2.2 规则

| 项 | 设计 |
| --- | --- |
| 输入 | 最多 **3 个元素容器** + **1 张符文版** |
| 输出 | 1 格（仪式完成后生成，只能取、不能放） |
| 时间 | 每张符文版定义（示例：10 秒） |
| 消耗 | 输入的元素容器**按仪式要求扣数量**，容器本身归还 |
| 衰变 | 仪式过程中**照常衰变**（这是核心张力：你放进去的元素可能在你眼前变坏） |
| 中断 | 拿走任意输入 / 破坏方块 → 进度清零，材料退回 |

> **"仪式中元素仍在衰变"是我建议保留的机制**：它让"先把材料备齐再来"变成一种玩家技巧，
> 也让符文柜（免疫衰变）有了存在意义。如果你觉得太惩罚，可以改成"仪式期间暂停衰变"。

### 2.3 第一批符文（3 张，够撑起一个阶段）

| 符文版 | 输入 | 输出 | 用途 |
| --- | --- | --- | --- |
| **聚敛符文** | 任意元素 ×4 | 1 份**该元素的稳定形态**（衰变计时归零） | 把快坏的元素"救回来" |
| **压印符文** | 死寂尘 ×8 | **死寂物质块** ×1 | 省手工合成 |
| **解离符文** | 任意衍生元素 ×2 | 退回**其母元素** ×1 | 回收，但亏一半 |

> 这三张刻意只做"元素的搬运与整形"，**不引入新物品** ——
> 目的是先把仪式台的机制跑通，新产物留到阶段 05。

## 三、符文版（Rune Plate）

### 3.1 是什么

一张**消耗品**（不是永久解锁）。放进仪式台后，仪式完成即消耗。

理由：消耗品让"符文版"本身变成一种可量产、可囤积的资源，接得上总纲 12.1 的"在家里量产"原则。
如果你想要"一次性解锁、之后无限用"的知识型设计，告诉我就行 —— 这决定了后期节奏。

### 3.2 怎么造

不做新的工作台，直接用**原版工作台**合成：

| 符文版 | 配方（3×3） |
| --- | --- |
| 聚敛 | 死寂尘 ×4 + 树叶 ×4 + 任意元素瓶 ×1（居中） |
| 压印 | 死寂尘 ×4 + 深板岩 ×4 + 火元素瓶 ×1（居中） |
| 解离 | 死寂尘 ×4 + 紫水晶碎片 ×4 + 影元素瓶 ×1（居中） |

> 刻意用"死寂尘 + 常见方块 + 一个元素"的三段式，配方形状统一，玩家一眼能记住。

### 3.3 外观

物品图标 = 一块**刻着纹路的石片**，纹路颜色区分符文类型（聚敛=青、压印=灰、解离=紫）。
需要 3 张新素材（`rune_gather.png` / `rune_press.png` / `rune_split.png`）。

## 四、符文柜

### 4.1 定位

**第一个"完全免疫衰变"的仓储**，但有代价：要**供能**。

| 仓储 | 倍率 | 代价 | 阶段 |
| --- | --- | --- | --- |
| 普通箱子 | ×1.0 | 无 | 原版 |
| 石制密封仓 | ×0.5 | 占地、9 格 | 02（已有） |
| 元素小包 | ×0.8 / ×0.5 | 烧冷却剂 | 02（已有） |
| **符文柜** | **×0（不衰变）** | **持续消耗符文能量** | 04 |

### 4.2 供能

- 柜子有 **1000 点能量**，装满时约可持续 **3 个游戏日**
- 能量来源：**把元素容器塞进"供能槽"**，按元素价值折算（水 5 / 草 10 / 火 20 / 光 40 …）
- 能量耗尽 → 退回普通箱子效率（×1.0），**不会损坏内容物**
- 柜面上的 **25 像素掩膜**（素材已到）随能量高低分 4 档发光 —— 玩家不用打开就知道还有没有电

### 4.3 容量

**27 格**（3×9），界面复用原版箱子贴图 + 自己的一格供能槽。

> 素材里的 `rune_cabinet_charge.png` 正好是 25 像素的储能区，
> 我们按 `source/rune_charge_region.json` 的坐标实现 4 档亮度。

## 五、实现方案

```
block/
├── BasicRitualAltarBlock.java      （新）仪式台方块
├── BasicRitualAltarBlockEntity.java（新）3 输入 + 1 符文 + 1 输出 + 进度
├── RuneCabinetBlock.java           （新）符文柜
└── RuneCabinetBlockEntity.java     （新）27 格 + 能量 + 掩膜亮度

menu/  BasicRitualAltarMenu / RuneCabinetMenu
client/ 两个 Screen（仪式台自定义贴图，符文柜复用箱子贴图）

item/
└── RunePlateItem.java              （新）三种符文版（用枚举 + 数据组件区分）

data/elemental_verse/rune/          （新）符文定义（数据驱动，方便以后加）
```

### 5.1 数据驱动

符文定义写成 **datapack JSON**，而不是写死在代码里：

```json
{
  "inputs": [{"element": "any", "count": 4}],
  "output": {"item": "elemental_verse:element_vial", "components": {"elemental_verse:element": "water"}},
  "duration": 200,
  "energy_cost": 0
}
```

这样以后加符文只写 JSON，不动 Java。

## 七、验收标准

- [ ] 能造**基础仪式台**（配方待定，见第八节）
- [ ] 放进 **4 个水元素 + 聚敛符文** → 10 秒后得到 **1 个计时归零的水元素瓶**，符文被消耗
- [ ] 仪式进行中**把元素拿出来** → 进度清零，材料退回
- [ ] 仪式进行中元素**仍在衰变**（若第 1 条选"要"）
- [ ] 能造**符文柜**，放进去的元素**完全不衰变**
- [ ] 柜面**随能量高低变亮/变暗**（4 档）
- [ ] 能量耗尽后柜内元素**按普通速度衰变**，内容物不损毁
- [ ] 塞元素进供能槽 → 能量回升，柜面重新变亮
