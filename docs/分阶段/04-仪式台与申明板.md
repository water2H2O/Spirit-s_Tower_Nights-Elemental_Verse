## 一、这一阶段到底在造什么

作者原话：

> **有点像化学，中间造成大量火元素伤害是现象，也是这个包里的魔法。**

所以这一阶段造的不是"施法功能"，而是**一门化学**：

```
物质：元素值（六条轴 + 负光，可以正负小数）
   ↓
反应式：消耗哪些元素值 → 什么条件 → 产生什么现象 → 返还什么
   ↓
申明板：一条反应式被写下来，成为一件"法术"
   ↓
仪式台：玩家把元素凑出来，触发反应
```

**判定依据就是算出来的元素值本身** —— 玩家放进去的东西，加起来等于哪条反应式，就出哪个现象。

## 二、物质：元素值

### 2.1 六条基础轴

```
火 fire · 水 water · 地 earth · 风 wind · 草 grass · 光 light
```

**暗不是独立轴，是负的光**（{光:−1}）。

### 2.2 每种元素 = 一个式子

| 元素 | 元素值 | 说明 |
| --- | --- | --- |
| 火 | {火:1} | |
| 水 | {水:1} | |
| 地 | {地:1} | |
| 风 | {风:1} | |
| 草 | {草:1} | |
| 光 | {光:1} | |
| **暗** | {光:−1} | 负光 |
| **霜** | {火:−0.5} | 纯克制剂 |
| 冰 | {火:−1} | 纯克制剂 |
| 砂 | {水:−0.5} | 纯克制剂 |
| 金 | {水:−1} | 纯克制剂，本期不产出 |
| 芽 | {地:−0.5} | 纯克制剂 |
| 木 | {地:−1} | 纯克制剂 |
| 电 | {草:−0.5} | 纯克制剂 |
| 烬 | {光:−0.5} | 纯克制剂 |
| 晨 | {光:2} | 光系例外 |
| 影 | {光:−1.5} | 纯克制剂 |

> **2026-10-21 简化口径（以代码为准）**：二级元素不再是“基础元素 + 修饰”的
> 化合物，而是**纯克制剂** —— 只有一条负轴，不提供正面分量，也不作为施法供能材料。
> 早期“霜 = 水 + 负火”“冰 = 水 + 负火”的写法已废弃。
>
> 双元素法术仍然保留“主料 × 辅料”的组合，但**释放只扣主轴**；辅料在写板时
> 投入，释放不按次扣。这是刻意的玩法简化，避免一次施法同时掏空两条轴。

### 2.3 强度

**强度 = 各分量绝对值之和**

| 元素 | 元素值 | 强度 |
| --- | --- | --- |
| 火 | {火:1} | 1 |
| 霜 | {火:−0.5} | 0.5 |
| 冰 | {火:−1} | 1.0 |

强度**只用来缩放现象的强弱**，不再是扣瓶数的依据（扣瓶数改用反应式的消耗，见第三节）。
二级元素强度低且只做负向抵消，**不能给同轴法术供能**。

## 三、反应式：魔法的定义

### 3.1 一条反应式长什么样

作者给的例子：

> 消耗：**1 草 + 1 火** → 无条件 → 造成**大量持续的火元素伤害**，返还：**无**

翻译成数据结构：

| 字段 | 内容 |
| --- | --- |
| **消耗** | `{草:1, 火:1}` |
| **条件** | 无（可选：纯净度、目标状态、位置） |
| **现象** | 持续火元素伤害，强度由投入的总元素值决定 |
| **返还** | 无（也可能返还某种元素，比如烧完剩烬） |

### 3.2 三种组成部分

**① 消耗（输入）**
玩家投入的元素容器，把它们的元素值**加起来**，就是输入向量。

**② 条件（门槛）**
本阶段只支持两类：
- **无条件**
- **纯净度阈值**（仪式台环境的纯度，见 5.4）

> 条件不满足 → 反应**不发生**，材料退回。这和"跑偏"是两回事。

**③ 现象（输出）**
实际效果。现象本身也用元素值描述强弱，比如"燃烧"就是**往目标身上灌火元素值**：

```
燃烧 = 目标获得 {火: +3}（持续 N 秒，每秒结算一次伤害）
```

### 3.3 匹配：算出来的向量决定出哪个现象

玩家投入的元素值**相加**得到总输入向量，然后按**两级**匹配：

| 优先级 | 匹配方式 | 例子 |
| --- | --- | --- |
| **1. 精确配方** | 输入向量与反应式的消耗**相等**（容差 0.01） | `{草:1, 火:1}` → 燃烧 |
| **2. 主成分兜底** | 找不到精确配方时，按**主成分律**生成通用现象 | `{火:5}` → 火类通用现象，强度按 5 缩放 |

> **主成分律**（原理文档第五节）：总向量里绝对值最大的轴决定现象**类别**，
> 其余分量只做修饰；并列时按 `火 > 水 > 草 > 地 > 风 > 光` 裁决；全归零 = 湮灭。
>
> 有了第二级，玩家永远可以"扔一堆火"得到一个大火，而不是对着"没有对应配方"发呆。

> **为什么要有第二级**：不然"1 个火"和"9 个火"就得分两条配方写，
> 快速扩张时会爆炸。第一级留给**真正的化学**（1草+1火），
> 第二级兜住"同一种东西扔很多"的朴素情况。

**两条都匹配不上 → 无反应**，材料退回，行为栏提示「这些元素凑不出反应」。

### 3.4 二级元素：只做克制剂（简化后）

二级元素现在是**纯负值**，不再参与“化合物”式的组合。它们的主要用途是抵消：

| 组合 | 加起来是 | 结果 |
| --- | --- | --- |
| 火 + 冰 | {火:1} + {火:−1} = {火:0} | **湮灭**：净值归零，只留余热 |
| 水 + 金 | {水:1} + {水:−1} = {水:0} | **湮灭** |
| 草 + 木 | {草:1} + {地:−1} | 不是同轴，按主成分律走草类，负地只做修饰 |
| 火 + 霜 | {火:1} + {火:−0.5} = {火:0.5} | 火类，但强度减半 |
| 暗 + 光 | {光:−1} + {光:1} = {光:0} | **湮灭**，天然成立 |

> **真正需要“双元素”的地方，仍然是基础元素之间的组合**（例如 1 水 + 1 风 =
> 暴风雪、1 草 + 1 火 = 燃烧）。二级元素只负责“把某条轴压下去”或“凑出零”。
> 早期“霜 + 火 = 蒸汽”“霜 + 霜 = 结冰”那套化合物玩法已简化掉，不再作为设计目标。

### 3.5 形：法术的"写法"（本期只留字段）

反应式决定"能做什么"，**形决定"怎么做"** —— 两者正交，这是自由度的来源。

| 字段 | 取值 | 本期 |
| --- | --- | --- |
| **形态** | 自身 / 发射 / 交互 | ✅ 只做**发射**（丢出去），其余灰 |
| **时序** | 即时 / 延时 N / 持续 N | ✅ 只做**即时** |
| **状态** | 松手即停 / 元素场不足 / 超出范围 | 🔒 固定「松手即停」 |
| **附属** | 稳定 / 延长 / 相位 / 急速 / 冷凝 … | 🔒 全部灰 |

> **形属于知识**：加新魔法 = 加一条形，**元素值一条都不用改**。
> 反过来，不要把形塞进元素值里（比如造一个"发射元素"）—— 那会把两个正交维度压平。

### 3.6 守恒三律（数值护栏）

| 法则 | 内容 |
| --- | --- |
| **守恒** | 现象的当量 **≤** 投入的强度 |
| **饱和** | 单次投入超过阈值（值 3 / 9 个）后不再线性变强，多出的转成余热 |
| **余热** | 余热 = 强度 × (2 − 纯净度) |

> 饱和这条最重要：它让"多投料"变成有上限的投入，而不是"64 个火 = 秒天秒地"。

### 3.7 反应表放在数据包里

```json
{
  "id": "burn",
  "consume": { "grass": 1, "fire": 1 },
  "condition": { "purity_min": 0.0 },
  "phenomenon": {
    "type": "elemental_verse:sustained_element_damage",
    "element": "fire",
    "per_second": 3.0,
    "duration": 100
  },
  "refund": {}
}
```

加一条魔法 = 写一个 JSON，不动 Java。

## 四、申明板

### 4.1 两种用法

| 用法 | 说明 | 本期 |
| --- | --- | --- |
| **直接释放** | 手持申明板右键，按申明触发反应 | ✅ |
| **当锻造模板** | 把申明刻到工具上，由工具触发；不同魔法载体改变施法模式 | ✅ 只做**剑** |

### 4.2 申明板上写的是什么

**一条反应式的引用 + 一组形**：料（元素 + 元素值）+ 形（形态 / 时序 / 状态）。

空申明板 → 写了字段 → **已定义申明板**。释放**不会消耗**申明板（它是一块写好的板子），
但每次释放只扣**主轴材料**（4 / 8 / 16 点）；辅料和态在写板时已经付过，释放不按次扣。
符文柜也可以吃掉已定义板当燃料（第九节）。

## 五、仪式台

### 5.1 两种模式

| 模式 | 输入 | 产出 | 本期 |
| --- | --- | --- | --- |
| **定义（写入）** | 元素 + **空申明板** | 已定义的申明板 | ✅ |
| **刻印（剑）** | 已定义的申明板 + 剑 | 带申明的剑 | ✅ 只做剑 |
| **引用（触发）** | 已定义的申明板 | 立即触发反应 | ⏸ 未做 |

### 5.2 三个投入口（当前实现：三口都参与）

| 投入数量 | 元素值档位 |
| --- | --- |
| 1 | **1** |
| 3 | **2** |
| 9 | **3** |
| （27） | （4 · **质变**，后续） |

当前实现：

| 口 | 作用 | 写板消耗 | 施法消耗 |
| --- | --- | --- | --- |
| **① 主料** | 进入 `inputValue()`，决定反应匹配 | 1 / 3 / 9 | **按档位 4 / 8 / 16 点** |
| **② 辅料** | 也进入 `inputValue()`（例如 1 火 + 1 水 = 蒸汽） | 1 / 3 / 9 | **不扣**（写板时已付） |
| **③ 态** | 不进入 `inputValue()`，只生成 `SpellParams` 六参数 | 1 / 3 / 9 | **不扣**（写板时已付） |

> 也就是说：写一张板要付 **主料 + 辅料 + 态 + 空板**；释放一次**只付主轴**。
> 辅料和态是“配方”，一次性刻进板子里；不是每次施法都再烧一遍辅料和 9 个风。
> 这是 2026-10-21 定下的玩法简化：双轴同时扣成本太高，保留组合但只收主轴的钱。

### 5.3 相邻容器（当前实现）

仪式台**水平四周紧挨**密封舱 / 符文柜 / 普通容器时：

- 主料槽为空时，自动读取相邻容器里的**第一种**可用元素（不是 9 选 3 UI）
- 拿走产出时会**从那个容器里扣掉**对应的元素；不会再出现“白拿”
- 本次仍然只用这一个来源；多选 UI 留到后续

> 原设计“列出最多 9 种、选 3 种、且禁用背包/小包”的 UI 还没做；
> 当前只做了“能读、能扣”的最小闭环。

### 5.4 纯净度

保留 `getPurity(level, pos)` 接口；污染到阶段 06 才有，本期固定为 1.0（纯净）。

反应式可以用 `purity_min` 当条件。**后续饰品**让玩家读到具体数值，
所以本期**不做常驻 UI**。

## 六、释放：剑的升级（本期只做剑）

**当前实现（2026-10-18 调整）**：不走原版锻造台，而是在仪式台中间加一个剑槽。

```
仪式台： 已定义申明板（template，保留）
       + 剑（base，被消耗）
                        ↓
            刻了这条反应的剑（申明存在数据组件里）
                        ↓
        攻击命中 → 检查并扣除消耗 → 触发反应
```

- 剑槽在仪式台贴图原来的“箭头”位置；屏幕补画了槽位框并标“剑槽”
- **申明板不消耗**（可以继续做下一把剑）；剑被消耗，避免复制
- 触发时按**主轴**从背包扣元素容器（4 / 8 / 16 点）；辅料/态不按次扣；**不够就不触发**并提示
- 刻在剑上的板子如果凑不出反应，攻击时只提示「这些元素凑不出反应」，不扣材料

## 八、发现机制

反应式如果玩家学不到，"自由"就变成"不知道能干什么"。本期只做**最小的一条**：

- **顿悟**：第一次凑出有效的未知组合 → 行为栏提示 + 记入「已知反应」图鉴
- **图鉴**：一个只读界面，列出见过的组合与结果（否则玩家第二次就忘了）

残卷、试验台留到阶段 07（灾变前遗迹）。

## 九、符文柜

- 只接受**声明霜 / 冰**的申明（原理是维持低温）
- **霜/冰的元素值档位越高，维持越久**（直接落在元素值上，不另做耐久）

| 投入的申明 | 维持时长（建议） |
| --- | --- |
| 霜 · 值 1 / 2 / 3 | 0.5 / 1 / 2 游戏日 |
| 冰 · 值 1 / 2 / 3 | 1 / 2 / 4 游戏日 |

其余：27 格、通电时柜内完全不衰变、断电退回 ×1.0、掩膜 4 档亮度。
