## 一、这一阶段要立的地基

这一阶段不做"一个玩法"，而是立**一套数值语言**。后面所有法术、二级元素、符文柜，
全部用这套语言描述。

```
元素值（六条轴 + 负光）
   ↓
申明板（把元素值写成一条"申明"）
   ↓
仪式台（定义模式：写入）  /  已定义的申明板（引用模式：直接释放、或当锻造模板用）
```

**本期只做"定义"这一半**，引用模式的入口先留好。

## 二、申明板

### 2.1 两种用法

| 用法 | 说明 | 本期 |
| --- | --- | --- |
| **直接释放** | 手持申明板右键，按申明的内容施法 | ✅ 做 |
| **当锻造模板** | 把申明"刻"到工具上，由工具触发；**不同魔法载体改变施法模式** | ✅ 只做**剑** |

### 2.2 状态

| 状态 | 说明 |
| --- | --- |
| **空申明板** | 没有写任何字段 |
| **已定义申明板** | 写了元素 + 操作 + 元素值，可以释放、可以当模板 |

> 申明板**不会因为释放而消失** —— 它是一块"已写好的板子"。
> （符文柜那条会**吃掉**申明板当燃料，见第七节）

## 三、仪式台

### 3.1 两种模式

| 模式 | 输入 | 产出 | 本期 |
| --- | --- | --- | --- |
| **定义（写入）** | **元素** + **空申明板** | 已定义的申明板 | ✅ **只做这个** |
| **引用（触发）** | **已定义的申明板** | 立即施法 | ⏸ 界面留灰 |

> 作者定："现在先做前者"。

### 3.2 元素投入：三个入口，但只有一个生效

界面有 **3 个元素投入口**，每个口可以放同一种元素的多份：

| 投入数量 | 元素值档位 |
| --- | --- |
| 1 | **1** |
| 3 | **2** |
| 9 | **3** |
| （27） | （4 · **质变**，后续再做） |

**本期只有第 1 个投入口参与生效**。第 2、3 口可以放东西、会存进申明板，
但**不影响效果** —— 先把"三投入口"这套结构定下来，等质变/组合规则明确了再启用。

> 为什么现在就把三个口做出来：三口的**界面、数据、消耗逻辑**是同一套，
> 以后启用只改"哪几个口参与计算"，不用重做界面。

### 3.3 相邻容器加成（作者口述）

当仪式台的**四周紧挨着**密封舱 / 符文柜时：

- 仪式台可以直接读取容器内的元素，**最多列出 9 种**供玩家挑选
- 玩家可以从中选**最多 3 种**作为本次仪式的投入
- **此时不能再使用元素小包和背包里的元素** —— 本次仪式的元素**只能来自容器**

> 这条把"仓储"和"仪式"从两个孤立系统变成了一体：
> 仓库堆得越整齐，仪式台能直接选的东西越多。

### 3.4 纯净度

保留接口。周围 16 格的污染值影响偏差与余热（污染在阶段 06 才有，本期固定为"纯净"）。

**后续**会有饰品让玩家读到详细数值 —— 所以本期**不要**把这些数字做成常驻 UI，
留 `getPurity()` 就够了。

## 四、元素值框架（本阶段的核心重构）

### 4.1 六条基础轴

```
火 fire · 水 water · 地 earth · 风 wind · 草 grass · 光 light
```

**暗不是独立轴，是负的光**（{光: −1}）。

### 4.2 每种元素 = 一组元素值

元素值是一个**六维向量**，每个分量可以是正、负、小数：

| 元素 | 元素值 | 说明 |
| --- | --- | --- |
| 火 | {火:1} | |
| 水 | {水:1} | |
| 地 | {地:1} | |
| 风 | {风:1} | |
| 草 | {草:1} | |
| 光 | {光:1} | |
| **暗** | {光:−1} | 负光 |
| **霜** | {水:1, 火:**−0.5**} | **作者已给的定义** |
| 冰 | {水:1, 火:−1} | 比霜更"冷" |
| 砂 | {地:1, 水:−0.5} | *建议值，待你定* |
| 电 | {风:1, 光:0.5} | *建议值* |
| 烬 | {火:1, 光:−0.5} | *建议值* |
| 芽 | {草:1, 水:0.5} | *建议值* |
| 木 | {草:2} | *建议值（草→芽→木，越走越凝）* |
| 晨 | {光:1, 火:0.5} | *建议值* |
| 影 | {光:−1, 草:−0.5} | *建议值* |
| 金 | {地:2, 火:1} | 本期不产出，先定义 |

> **二级元素（霜/砂/电/烬/芽/木/晨/影）的意义就在这里**：
> 它们不是"另一个元素"，而是**元素值的组合式**。
> 霜之所以能降温，是因为它带着"负的火"。

### 4.3 强度与消耗

**强度 = 元素值各分量绝对值之和**（L1 范数）

| 元素 | 元素值 | 强度 |
| --- | --- | --- |
| 火 | {火:1} | **1** |
| 霜 | {水:1, 火:−0.5} | **1.5** |
| 冰 | {水:1, 火:−1} | **2** |

**施法消耗**：要消耗的容器数量 = **⌈强度⌉**，容器种类 = **该元素本身**

- 一级火魔法 → 强度 1 → **消耗 1 个火元素瓶**（与作者举的例子一致）
- 霜魔法 → 强度 1.5 → **消耗 2 个霜瓶**
- 冰魔法 → 强度 2 → **消耗 2 个冰瓶**

> 如果要改成"按分量分别收钱"，改动只在 `ElementValue.cost()` 一个方法里。

### 4.4 为什么这是一次"底层重写"

现在的代码是：`ElementType` 枚举 + 一堆 `if (type == ICE)` 的硬判断。

改成：

```
ElementAxis      枚举（火/水/地/风/草/光）
ElementValue     不可变六维向量 + 加减 + 强度 + 消耗
ElementType      改为携带一个 ElementValue，而不再只是"名字 + 链"
```

好处是所有二级元素的效果都能写成**算法**，不用再一个个写 `if`。
比如霜的降温效果 = 看 value 里有没有"负火"，有多少，就降多少度。

## 五、释放：剑的升级（本期只做剑）

### 5.1 流程

```
原版锻造台：  剑（base） + 已定义的申明板（template） + 魔法载体（addition）
                          ↓
              附了这条申明的剑（数据组件里存着申明）
                          ↓
        手持它攻击 → 消耗元素瓶 → 触发申明效果
```

- **魔法载体（addition）改变施法模式**：本期**只留结构**，
  先只支持一种载体，把"模式"字段挂在申明上
- 触发时从**玩家背包**里扣元素瓶，不够就**不触发**并给提示

### 5.2 为什么先做剑

剑的触发时机最明确（攻击命中），不用处理"持续施法""瞄准方块"这些形态问题。
等元素值框架稳了，再往别的工具上扩。

## 七、符文柜

### 7.1 只能吃"霜 / 冰"的申明

符文柜的供能**不是任意申明板**，而必须是**声明霜或冰**的申明 —— 它的原理是维持低温。

| 喂进去的申明 | 维持时长 |
| --- | --- |
| 霜 · 元素值 1 | 短 |
| 霜 · 元素值 2 | 中 |
| 霜 · 元素值 3 | 长 |
| 冰 · 元素值 1~3 | 比同档霜**更长** |

> **"冰/霜元素值越高，持续时间越久"** 直接落在元素值上，不需要另做一套耐久。
>
> 具体秒数待定（建议：霜 1/2/3 档 = 0.5 / 1 / 2 个游戏日；冰同档 ×2）。

### 7.2 其余规则不变

- 27 格（3×9）
- 通电时柜内元素**完全不衰变**
- 断电退回 ×1.0，内容物不损毁
- 柜面 25 像素掩膜按能量分 4 档亮度

## 十、验收标准

- [ ] 仪式台能开，**三口**都在，第 2/3 口标灰并提示"尚未启用"
- [ ] 放 **1 个火元素** + 空申明板 → 得到「火 · 元素值 1 · 释放」的申明板
- [ ] 放 **9 个火元素** → 得到「元素值 3」的申明板
- [ ] 手持已定义的申明板右键 → **直接释放**，消耗 ⌈强度⌉ 个对应容器
- [ ] 背包里元素瓶不够 → **不释放**，给提示
- [ ] 申明板放锻造台模板槽 + 剑 → 得到**带魔法的剑**
- [ ] 用那把剑攻击 → **消耗元素瓶并触发效果**
- [ ] 仪式台紧挨密封仓 → 界面列出容器内元素（**最多 9 种**），可选 **3 种**；
      此时**背包和小包里的元素不可用**
- [ ] 施法后**区块余热上升**，之后缓慢下降（调试命令可见）
- [ ] 符文柜：喂**霜**的申明 → 柜内不衰变；**元素值 3 的霜**比元素值 1 维持更久；
      喂**火**的申明 → **不接受**
