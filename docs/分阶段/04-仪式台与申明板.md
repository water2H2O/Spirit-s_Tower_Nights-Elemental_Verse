## 一、这一阶段真正的目标

总纲第五章第一句：

> **申明板是整个模组的心脏。** 它既是施法的手段，也是与晶裔交易的货币，还是全模组唯一的知识载体。

所以这一阶段不是"再加一个方块"，而是**让模组第一次能"施法"**：

```
仪式台  ──写入──▶  申明板  ──驱动──▶  法术效果 / 余热 / 符文柜
（放材料的地方）    （模组心脏）        （世界开始变脏）
```

之前几阶段玩家一直在"攒元素"，这一阶段开始**元素终于能变成动作**。

## 二、基础仪式台

### 2.1 形态与理由

**单方块，右键开界面。** 总纲 5.1 明确写了：

> 仪式台做成工作台结构（一个方块，右键打开界面），**不做多方块结构** —— 学习成本必须低。

界面上**三个投入格**：

| 格 | 放什么 | 作用 |
| --- | --- | --- |
| ① 申明板 | 一块申明板 | 写字段的载体 |
| ② 元素材料 | 元素容器（可放多份） | 决定**条目种类**与**量级** |
| ③ 附属材料 | 元素容器 | 决定**效果细节**与**时序**（05 阶段才生效，先留格） |

外加：**拼字段面板**（见第四节）、**注入按钮**、**输出格**（拿回注入后的申明板）。

### 2.2 纯净度（先接 0）

总纲 5.1：仪式台周围 16 格的污染值决定纯净度，影响偏差率与余热。

**本阶段没有污染系统**（瘴素在阶段 06），所以先固定为「纯净」：
接口留好 `getPurity(level, pos)`，永远返回 1.0，06 阶段再真正读污染。

## 三、申明板

### 3.1 是什么

一块**可写字段的石板**，写完之后拿去仪式台"注入"，注入完成的申明板=**一个法术**。

它同时是：
- **施法手段**（本阶段要做的）
- **交易货币**（与晶裔，阶段 08）
- **知识载体**（知识晶复制，阶段 08）

### 3.2 六个字段与开放节奏（总纲 5.2）

| 字段 | 取值 | 本阶段 |
| --- | --- | --- |
| **元素** | 地 / 水 / 风 / 火 / 草 / 光 / 暗 | ✅ **开放** |
| **操作** | 聚集 / 塑形 / 释放 | ✅ **开放**（但见 3.4：只有"释放"有实际效果） |
| **形态** | 自身 / 发射 / 交互 | 🔒 灰着（阶段 05） |
| **量级** | 少 / 中 / 多 | — **由投入元素数量决定，玩家不选**（总纲 5.2） |
| **附属** | 稳定 / 延时 / 延长 … | 🔒 灰着（阶段 05） |
| **时序** | 即时 / 延时 / 持续 | 🔒 灰着（阶段 05） |
| **状态** | 松手即停 … | 🔒 固定「松手即停」 |

**界面上灰掉的字段不是隐藏，而是显示成灰**（总纲 5.2 的"先看清楚，再动手"）。

### 3.3 量级由数量决定

| 投入元素数量 | 量级 | 效果强度 |
| --- | --- | --- |
| 1 | 少 | 基础值 |
| 3 | 中 | ×2 |
| 9 | 多 | ×4 |

> 玩家**不选**量级 —— 投入多少就多强。这样"省着用"和"全力一击"是同一个操作的不同投入。

### 3.4 本阶段只做「释放」

三种操作里，**只有「释放」会真的产生效果**；「聚集」和「塑形」在界面上可选，
但注入后会提示「你还不知道怎么让它生效」—— 这是阶段 05 的钩子。

七种元素 × 释放，各一个效果：

| 元素 | 效果 | 备注 |
| --- | --- | --- |
| **火** | 点燃命中的方块 / 实体 | 经典、最直观 |
| **水** | 在命中处放水；对燃烧目标灭火 | |
| **地** | 在命中面放一块圆石墙 / 挖掉软方块 | 量级影响块数 |
| **风** | 把命中的实体推开 | 量级影响力度 |
| **草** | 催熟命中的作物 / 让草方块长草 | 量级影响范围 |
| **光** | 短暂照亮命中区域（放置光源） | |
| **暗** | 让命中实体短暂失明 | |

> 这七个效果刻意都**只作用于"命中点及其附近"**，不做投射物、不做持续施法 ——
> 那些是形态与时序字段的事（阶段 05）。

## 四、余热（先存不显）

总纲 3.4：施法会让世界变脏。

**本阶段只做数值，不做可视化**：

- 每次施法给所在**区块**加一份余热（按元素与量级加权）
- 余热随时间缓慢衰减
- 存进区块的存档数据（`SavedData`），**调试命令查看**
- 06 阶段的瘴素会读它

> 为什么现在就做：没有余热，"法术"就只是免费的能力，玩家的行为不会被世界记住。
> 而余热系统一旦晚做，所有法术都得回头改一遍。

## 五、符文柜（本阶段收尾）

26 格仓储，**柜内元素完全不衰变**，但有代价：**吃申明**。

| 项 | 设计 |
| --- | --- |
| 容量 | **27 格**（3×9） |
| 效果 | 通电时柜内元素**衰变速度 ×0** |
| 供能 | **喂入已注入的申明板**，一块低级申明 = 约 1 个游戏日 |
| 断电 | 退回 **×1.0**（普通箱子），内容物不损毁 |
| 外观 | 作者素材的 **25 像素储能掩膜**，按能量分 **4 档**亮度 |

> **为什么用申明驱动而不是烧元素**：这样它就成了申明板的第一个"下游应用"——
> 玩家第一次需要用"自己写的法术"去维持一件东西，而不是又去挖矿。

### 6.1 数据驱动

"申明 → 效果"写成 **datapack JSON**，而不是一长串 switch：

```json
{
  "element": "fire",
  "operation": "release",
  "magnitude": "medium",
  "effect": "elemental_verse:ignite",
  "radius": 2.0
}
```

以后加元素、加效果都不用改 Java。

## 八、验收标准

- [ ] 能造**基础仪式台**并打开界面
- [ ] 界面里**元素 / 操作可选**，其余字段**灰着但可见**
- [ ] 放入申明板 + 1 个火元素 → 选「释放」→ 注入 → 得到写好的申明板
- [ ] 拿着写好的申明板右键 → **点燃面前的方块**
- [ ] 投入 **1 / 3 / 9** 个元素，效果范围**明显不同**
- [ ] 选「聚集」注入 → 提示「你还不知道怎么让它生效」
- [ ] 连续施法 20 次 → 调试命令查看**区块余热明显上升**，放置后**缓慢下降**
- [ ] 符文柜：喂入申明板 → 柜内元素**完全不衰变**；断电 → 恢复普通速度
