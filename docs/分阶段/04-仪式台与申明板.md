## 一、这一阶段到底在造什么

作者原话：

> **有点像化学，中间造成大量火元素伤害是现象，也是这个包里的魔法。**

所以这一阶段造的不是"施法功能"，而是**一门化学**：

```
物质：元素值（六条轴 + 负光，可以正负小数）
   ↓
反应式：消耗哪些元素值 → 什么条件 → 产生什么现象 → 返还什么
   ↓
申明板：一条反应式被写下来，成为一件"法术"
   ↓
仪式台：玩家把元素凑出来，触发反应
```

**判定依据就是算出来的元素值本身** —— 玩家放进去的东西，加起来等于哪条反应式，就出哪个现象。

## 二、物质：元素值

### 2.1 六条基础轴

```
火 fire · 水 water · 地 earth · 风 wind · 草 grass · 光 light
```

**暗不是独立轴，是负的光**（{光:−1}）。

### 2.2 每种元素 = 一个式子

| 元素 | 元素值 | 说明 |
| --- | --- | --- |
| 火 | {火:1} | |
| 水 | {水:1} | |
| 地 | {地:1} | |
| 风 | {风:1} | |
| 草 | {草:1} | |
| 光 | {光:1} | |
| **暗** | {光:−1} | 负光 |
| **霜** | {水:1, 火:**−0.5**} | **作者已给** |
| 冰 | {水:1, 火:−1} | 比霜更冷 |
| 砂 | {地:1, 水:−0.5} | *建议值* |
| 电 | {风:1, 光:0.5} | *建议值* |
| 烬 | {火:1, 光:−0.5} | *建议值* |
| 芽 | {草:1, 水:0.5} | *建议值* |
| 木 | {草:2} | *建议值* |
| 晨 | {光:1, 火:0.5} | *建议值* |
| 影 | {光:−1, 草:−0.5} | *建议值* |
| 金 | {地:2, 火:1} | 本期不产出 |

> **二级元素就是"分子"**：它们不是另一种元素，而是基础元素的**化合物**。
> 霜带负火，所以它能吸热 —— 这条以后所有二级元素都照这个方式定义。

### 2.3 强度

**强度 = 各分量绝对值之和**

| 元素 | 元素值 | 强度 |
| --- | --- | --- |
| 火 | {火:1} | 1 |
| 霜 | {水:1, 火:−0.5} | 1.5 |
| 冰 | {水:1, 火:−1} | 2 |

强度**只用来缩放现象的强弱**，不再是扣瓶数的依据（扣瓶数改用反应式的消耗，见第三节）。

## 三、反应式：魔法的定义

### 3.1 一条反应式长什么样

作者给的例子：

> 消耗：**1 草 + 1 火** → 无条件 → 造成**大量持续的火元素伤害**，返还：**无**

翻译成数据结构：

| 字段 | 内容 |
| --- | --- |
| **消耗** | `{草:1, 火:1}` |
| **条件** | 无（可选：纯净度、目标状态、位置） |
| **现象** | 持续火元素伤害，强度由投入的总元素值决定 |
| **返还** | 无（也可能返还某种元素，比如烧完剩烬） |

### 3.2 三种组成部分

**① 消耗（输入）**
玩家投入的元素容器，把它们的元素值**加起来**，就是输入向量。

**② 条件（门槛）**
本阶段只支持两类：
- **无条件**
- **纯净度阈值**（仪式台环境的纯度，见 5.4）

> 条件不满足 → 反应**不发生**，材料退回。这和"跑偏"是两回事。

**③ 现象（输出）**
实际效果。现象本身也用元素值描述强弱，比如"燃烧"就是**往目标身上灌火元素值**：

```
燃烧 = 目标获得 {火: +3}（持续 N 秒，每秒结算一次伤害）
```

### 3.3 匹配：算出来的向量决定出哪个现象

玩家投入的元素值**相加**得到总输入向量，然后按**两级**匹配：

| 优先级 | 匹配方式 | 例子 |
| --- | --- | --- |
| **1. 精确配方** | 输入向量与反应式的消耗**相等**（容差 0.01） | `{草:1, 火:1}` → 燃烧 |
| **2. 单物质强度** | 输入只有一种元素，且数量匹配 | `{火:9}` → 大火球，强度按 9 缩放 |

> **为什么要有第二级**：不然"1 个火"和"9 个火"就得分两条配方写，
> 快速扩张时会爆炸。第一级留给**真正的化学**（1草+1火），
> 第二级兜住"同一种东西扔很多"的朴素情况。

**两条都匹配不上 → 无反应**，材料退回，行为栏提示「这些元素凑不出反应」。

### 3.4 二级元素互相作用（后续重点）

这是作者强调要"后续也要考虑"的部分。举三个例子说明它为什么重要：

| 组合 | 加起来是 | 可能的现象 |
| --- | --- | --- |
| 霜 + 火 | {水:1, 火:0.5} | 不是"冷却"也不是"燃烧"，而是**蒸汽/沸腾** —— 一条新反应 |
| 霜 + 霜 | {水:2, 火:−1} | 接近冰的式子 → **结冰** |
| 暗 + 光 | {光:0} | **湮灭**：什么都不产生，但可能返还余热 / 打散附近元素 |

> 因为暗是负光，**暗 + 光 = 0** 是天然成立的，不需要特判。
> 这就是"元素值"这套设计真正的价值：**组合效应自己长出来，不用一条条写。**

### 3.5 反应表放在数据包里

```json
{
  "id": "burn",
  "consume": { "grass": 1, "fire": 1 },
  "condition": { "purity_min": 0.0 },
  "phenomenon": {
    "type": "elemental_verse:sustained_element_damage",
    "element": "fire",
    "per_second": 3.0,
    "duration": 100
  },
  "refund": {}
}
```

加一条魔法 = 写一个 JSON，不动 Java。

## 四、申明板

### 4.1 两种用法

| 用法 | 说明 | 本期 |
| --- | --- | --- |
| **直接释放** | 手持申明板右键，按申明触发反应 | ✅ |
| **当锻造模板** | 把申明刻到工具上，由工具触发；不同魔法载体改变施法模式 | ✅ 只做**剑** |

### 4.2 申明板上写的是什么

**一条反应式的"引用"**：元素 + 元素值 + 操作 + 条件。

空申明板 → 写了字段 → **已定义申明板**。释放**不会消耗**申明板（它是一块写好的板子）；
但符文柜会吃掉它当燃料（第八节）。

## 五、仪式台

### 5.1 两种模式

| 模式 | 输入 | 产出 | 本期 |
| --- | --- | --- | --- |
| **定义（写入）** | 元素 + **空申明板** | 已定义的申明板 | ✅ **只做这个** |
| **引用（触发）** | 已定义的申明板 | 立即触发反应 | ⏸ 界面留灰 |

### 5.2 三个投入口，本期只生效一个

| 投入数量 | 元素值档位 |
| --- | --- |
| 1 | **1** |
| 3 | **2** |
| 9 | **3** |
| （27） | （4 · **质变**，后续） |

**本期只有第 1 口参与计算**，第 2、3 口能放、能存，但**不影响结果**，界面上**标灰并提示"尚未启用"**。

> 为什么现在就把三口做出来：以后"1草+1火"这类**双输入反应**必须靠这三口。
> 三口的结构、数据、消耗逻辑是同一套，以后启用只改"哪几口参与计算"。

### 5.3 相邻容器（作者口述）

仪式台**四周紧挨**密封舱 / 符文柜时：

- 可以直接读取容器内的元素，**最多列出 9 种**供挑选
- 可从容器里选**最多 3 种**作为本次投入
- **此时不能再用背包和元素小包里的元素** —— 本次只吃容器里的

### 5.4 纯净度

保留 `getPurity(level, pos)` 接口；污染到阶段 06 才有，本期固定为 1.0（纯净）。

反应式可以用 `purity_min` 当条件。**后续饰品**让玩家读到具体数值，
所以本期**不做常驻 UI**。

## 六、释放：剑的升级（本期只做剑）

```
原版锻造台： 剑（base）+ 已定义申明板（template）+ 魔法载体（addition）
                        ↓
            刻了这条反应的剑（申明存在数据组件里）
                        ↓
        攻击命中 → 检查并扣除消耗 → 触发反应
```

- **魔法载体（addition）改变施法模式**：本期只留字段，先支持一种
- 触发时按**反应式的消耗**从背包扣元素容器；**不够就不触发**并提示
- 申明板刻进剑里之后**不消耗**（还能再做一把）

## 八、符文柜

- 只接受**声明霜 / 冰**的申明（原理是维持低温）
- **霜/冰的元素值档位越高，维持越久**（直接落在元素值上，不另做耐久）

| 投入的申明 | 维持时长（建议） |
| --- | --- |
| 霜 · 值 1 / 2 / 3 | 0.5 / 1 / 2 游戏日 |
| 冰 · 值 1 / 2 / 3 | 1 / 2 / 4 游戏日 |

其余：27 格、通电时柜内完全不衰变、断电退回 ×1.0、掩膜 4 档亮度。

## 十一、验收标准

- [ ] 仪式台能开，**三口**都在，第 2/3 口标灰并提示"尚未启用"
- [ ] 放 **1 个火** + 空申明板 → 得到「火 · 值 1」的申明板
- [ ] 放 **9 个火** → 得到「值 3」的申明板
- [ ] 手持已定义申明板右键 → **触发反应**，按反应式扣瓶
- [ ] 瓶不够 → 不触发 + 提示
- [ ] 投入 **2 个火 + 1 个草** → 若没有对应配方，提示「这些元素凑不出反应」并**退回材料**
- [ ] 剑放锻造台 + 申明板 → 得到**带魔法的剑**；攻击时扣瓶并触发
- [ ] 仪式台紧挨密封仓 → 列出容器内元素（**最多 9 种**），可选 **3 种**；
      此时**背包与小包不可用**
- [ ] 触发后**区块余热上升**，随后衰减（调试命令可见）
- [ ] 符文柜：喂**霜**的申明 → 不衰变；**值 3 比值 1 更久**；喂**火** → **不接受**
