## 1. 目标

让这条因果链在游戏里**跑通并且能被观察到**：

```
在同一个区块反复施法 → 那个区块的污染值上升 → 二阶后玩家开始"变脏"（浊化）→
站久了挖掘变慢/视野有雾 → 走出去会慢慢退 → 放元素方碑能把范围压回去
```

框架完成的判据只有一句：**能编译、能进游戏、能用 `/ev miasma` 把污染值和浊化值打出来看到它在变。**

不追求：手感、平衡、美术、音效、完整 UI。

## 8. 参考样本（好 / 坏）

### 好：区块级数据要带维度

```java
private static String key(ServerLevel level, BlockPos pos) {
    return level.dimension().location() + "@" + level.getChunk(pos).getPos().toLong();
}
```

### 坏：只用 `chunkPos`

```java
long key = level.getChunk(pos).getPos().toLong();   // 主世界与下界同坐标会互相污染
```

`ChunkHeat` 的第一版就这么错过，注释里留着记录（`heat/ChunkHeat.java` 第 66–74 行）。**照好样本写。**

### 好：每 N 秒的扫描要补时间

```java
long last = lastProcessed.getOrDefault(pos, now - SWEEP_INTERVAL);
int elapsed = (int) Math.max(0L, now - last);     // 轮转到这个区块时把少算的时间补上
lastProcessed.put(pos, now);
```

### 坏：每次固定 +5 秒

```java
advance(stack, 5 * 20);                            // 大世界里轮转间隔一长，整体就变慢
```
