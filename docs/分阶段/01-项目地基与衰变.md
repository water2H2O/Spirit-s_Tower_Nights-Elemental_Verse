## 一、这一阶段的目标

一句话：**把模板变成我们的仓库，并且让"瓶子里的元素会变质"这件事在游戏里成立。**

完成之后你能做的事：

1. 做出一个空元素瓶（玻璃 ×1）
2. 右键水，得到一个**装了水元素的瓶子**
3. 看着它在箱子里**自然而然地变成冰元素、再变成死寂物质**
4. 把死寂物质当建材摆出来

**这一阶段不做施法、不做污染、不做配方、不做元素采集系统。**
但就"会坏"这一件事，已经能玩出"仓储与节奏"的核心乐趣了。

## 二、物品清单（21 个）

### 2.1 载体：元素瓶

**元素不是"拿在手上的一块石头"，是装在瓶子里的东西。**

| 物品 | ID | 说明 |
| --- | --- | --- |
| **元素瓶** | `element_vial` | **唯一载体**。空着的时候是空瓶；装上元素后靠数据组件区分装了什么 |
| **折射棱镜** | `refraction_prism` | 光的专用采集容器（本轮不做，先占位注册） |
| **聚影瓶** | `shadow_bottle` | 暗的专用采集容器（本轮不做，先占位注册） |

**「元素瓶」是同一个物品的多种状态**：

```
element_vial  +  元素组件（空）       →  显示为「空元素瓶」
element_vial  +  元素组件（water）    →  显示为「水元素瓶」
element_vial  +  元素组件（ice）      →  显示为「冰元素瓶」
```

> **这样做的三个好处**：
> ① 采集出来天然就是"装着东西的瓶子"，符合直觉；
> ② 21 个物品而不是 27 个，注册表干净；
> ③ 以后加新元素只是加一个枚举项，不用再加物品。

**空瓶的获取（本阶段唯一的入口配方）**：

| 配方 | 内容 | 说明 |

| **空元素瓶** | **玻璃 ×1** | **极其便宜，游戏第一天就能做。这是整个模组的门** |

## 三、衰变机制（本阶段的技术核心）

### 3.1 怎么实现"会坏"

**每 20 tick（1 秒）扫一次，到点就换。**

```
每秒一次：
  遍历「已加载」的、装着元素的瓶子：
      它的计时器 += 20 tick
      超过阶段①时长  → 换成衍生元素
      超过阶段①+②时长 → 换成死寂物质（瓶子消失）
```

**关键点：只算「已加载」的。**

| 情况 | 行为 |
| --- | --- |
| 物品在**已加载区块**的箱子里 | 正常衰变 |
| 物品在**玩家背包里** | 正常衰变 |
| 物品掉在**已加载区块**的地上 | 正常衰变 |
| 区块**被卸载**（你走远了、退出游戏） | **不计时。世界停下，东西就停下** |

> 这条是你的意思，也确实更好懂、更好实现：
> **衰变是"世界在跑的时候才发生的事"，不是一个挂在墙上的钟。**
> 好处是玩家能理解（"我走了它就不坏了"），实现也简单（不用处理离线时间差），
> 而且给玩家一个真实的策略：**"把快坏的东西留在没人的地方"** —— 这挺有味道的。

**数据组件**：

| 组件 | 类型 | 用途 |
| --- | --- | --- |
| `elemental_verse:element` | `ElementType`（枚举） | 瓶子里装的是什么；`empty` 表示空瓶 |
| `elemental_verse:decay_timer` | `int`（tick 累计） | 已经过的时间 |

### 3.2 扫描怎么才不卡（性能方案）

"每秒遍历所有物品"听起来很吓人，实际上范围是可控的：

| 扫描对象 | 做法 |
| --- | --- |
| **玩家背包** | 每秒一次，每个玩家约 40 格。**这点开销可以忽略** |
| **已加载区块的容器** | 不用遍历每一个方块。**让"装了元素的方块实体"自己注册一个慢速 tick**（每 20 tick 一次） |
| **地上的掉落物** | 掉落物实体本身就在 tick，直接挂上去 |

**结论**：不需要"全世界大扫描"，是**事件驱动的慢速 tick**，每个容器自己管自己的东西。
100 个箱子 = 每秒 100 次极轻量的检查。

**兜底**：`EVConfig` 给一个"每秒最多检查多少个容器"的上限，超了就分摊到多个 tick 完成
（防止有人造 10000 个箱子把服务器拖死）。

### 3.3 衰变时长（第 1 版：**按"秒"排，方便你观察**）

以**秒**为单位（真实时间，1 秒 = 20 tick）。

| 元素 | 阶段① | 阶段② | 全程 |
| --- | --- | --- | --- |
| **水** | **20 秒** | **40 秒** | **1 分钟** ← 你要测的就是它 |
| 草 | 25 秒 | 50 秒 | 1 分 15 秒 |
| 火 | 30 秒 | 60 秒 | 1 分 30 秒 |
| 风 | 35 秒 | 70 秒 | 1 分 45 秒 |
| 地 | 45 秒 | 90 秒 | 2 分 15 秒 |
| 光 | 60 秒 | 120 秒 | 3 分钟 |
| 暗 | 60 秒 | 120 秒 | 3 分钟 |

**这是一版"观察用"的时长，不是最终数值。** 好处是：

- 你放下一个水元素瓶，**一分钟内能完整看到 稳定 → 冰 → 死寂物质 三个阶段**
- 不用敲 `/time add`，肉眼就能确认"自然变化"确实在发生
- 全部数值都在 `EVConfig` 里，**随时能改成正式值**

> **配置里同时提供两套预设**：`OBSERVE`（上面这套，秒级）/ `NORMAL`（总纲 2.3 那套，日级）。
> 默认用 `OBSERVE`，等你测完手感再切。

### 3.4 环境修正（本阶段做两条）

| 条件 | 修正 | 判定方式 |
| --- | --- | --- |
| **光**元素，所在位置亮度 ≤ 3 | **×2**（暗处加速） | 读所在位置的亮度 |
| **光**元素，亮度 ≥ 12 | **×0.5** | 同上 |
| **暗**元素，亮度 ≤ 3 | **×0.5** | 同上 |
| **暗**元素，亮度 ≥ 12 | **×2**（见光就散） | 同上 |
| **火**元素被用于合成 | 额外走 5 秒 | 合成事件里扣除 |
| 水元素在瘴素区 | ×0.5 | **瘴素还没做，留空接口** |

> 随身携带时，亮度取**玩家所在位置**的亮度。
> 所以"晚上带着光元素赶路"是有代价的。

### 3.5 玩家看到什么

| 反馈 | 做法 |
| --- | --- |
| **物品名** | **"水元素瓶" → "冰元素瓶"**（换的时候名字直接变） |
| **Tooltip** | **模糊描述，不给数字**："尚有余韵 / 渐趋沉寂 / 行将死寂" |
| **图标** | **本阶段先不做三态图标**（见 5.2 的取舍） |

> **不给数字是故意的。** 玩家应该能判断"该处理了"，但读不出秒表。

### 5.2 【取舍】图标三态：本阶段不做

"亮 → 暗 → 灰"的图标有三种做法：

| 做法 | 观感 | 风险 |
| --- | --- | --- |
| **A. 一条纹理到底** | 图标不变，名字与 tooltip 变 | 零风险 |
| B. 注册三个物品，到点替换 | 图标会换 | 和"一个物品 + 组件"的新方案直接冲突，**已废弃** |
| **C. 一个物品 + 按组件切换模型** | 图标会换 | **我在沙箱里无法验证**（无网络、无法编译） |

**本阶段走 A**：名字变了、tooltip 变了、"会不会坏"是能验证的。
**C 挪到阶段 02 单独做**，因为它是纯客户端渲染的事，和本阶段的"机制"是两码事，
混在一起会让验收变模糊。

> 换句话说：**机制是地基，图标是皮肤。** 先用 A 把地基浇好。

### 5.3 配置项

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `decay.preset` | `OBSERVE` | `OBSERVE`（秒级，方便观察）/ `NORMAL`（日级，正式手感） |

| `decay.globalMultiplier` | 1.0 | 全局速度倍率 |

## 十、实测后的第 3 轮修订（实现中暴露的问题）

第一次进游戏实测后，发现了三个必须现在修的问题。**结论都记在这里，因为它们是"设计没说清"导致的实现错误，不是随手写错。**

### 10.1 二级元素永远到不了死寂物质

**现象**：水 → 冰可以，冰 → 死寂物质永远不发生。

**根因（两个叠加）**：
1. 变形时把 `decay_timer` **清零**了，衍生元素从 0 重新计时；
2. 衍生元素**没有自己的时长条目**，于是计时在任何阈值上都不会触发。

**修法：计时改成「绝对口径」** —— 一个瓶子从装进去开始累计，**跨形态不重置**：

| 形态 | 阈值（观察预设） | 含义 |
| --- | --- | --- |
| 水（稳定） | 400 tick | 400 时变成冰，计时器仍是 400 |
| 冰（衍生） | 1200 tick = 400 + 800 | 1200 时变成死寂物质 |

即：**衍生元素的阈值 = 父稳定元素的「阶段① + 阶段②」**。
于是"水元素瓶全程 1 分钟"这个设计值自动成立，不需要给衍生元素单独配时长。

> 同时修掉一个笔误：`ICE` 的 `stage1` 曾经写成 `"frost"`，导致冰变成霜而不是死寂物质。

### 10.2 变形时物品"反复丢掉再捡起"

**现象**：手持元素瓶，到点时物品在手上闪一下，像被丢掉又捡起来。

**根因**：稳定元素 → 衍生元素时**物品本身没变，只变了数据组件**，但代码返回了一个新的
`ItemStack` 让调用方替换。客户端看到整格物品被换掉，就播放了换手动效。

**修法：只换组件的情况就地修改，不替换堆叠。**
只有"衍生元素 → 死寂物质"（物品类型真的变了）才返回新堆叠。

> 这条是模组里处理"会变的物品"的通用做法：**能改组件就不要换物品。**

### 10.3 图标：每个元素一个

用 `custom_model_data` 组件 + 物品模型 `overrides` 分发，**不需要任何客户端代码**：

- 组件值 = 枚举序号 + 1（0／缺失 = 空瓶）
- 序号由 `tools/generate-vial-models.py` **从 `ElementType.java` 解析生成**，
  避免手写 JSON 与枚举错位（错位表现为"图标张冠李戴"，很难查）
- **光**用折射棱镜贴图、**暗**用聚影瓶贴图（"特殊容器"的临时视觉表达）

贴图替换位置见 `docs/构建与验证.md`。

### 10.4 配方在配方书里看不到

**现象**：合成不了（实际是配方书里没有）。

**根因**：原版配方都配一条 advancement 才会在配方书里解锁；我们只有 recipe，没 advancement。
配方本身**一直是加载成功的**（原版 1290 条 + 我们 1 条 = 日志里的 1291）。

**修法**：补 `data/elemental_verse/advancement/recipes/misc/element_vial.json`。

### 10.5 按作者要求：去掉悬停描述

元素的"余韵/沉寂"这类描述**默认不再显示**。设定信息以后靠"特殊工具"查看 ——
这也是更符合世界观的做法：**不拿在手里就该看不懂。**
