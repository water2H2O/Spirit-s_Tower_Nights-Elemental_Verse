## 一、这一阶段的目标

一句话：**把模板变成我们的仓库，并且让"元素会坏"这件事在游戏里成立。**

完成之后你可以做的事：

1. 在创造模式里拿到 7 种元素
2. 把它们放进箱子，用 `/time add` 推时间
3. **看着它们从"稳定"变成"衍生"再变成"死寂"**
4. 把死寂物质当建材摆出来

**这一阶段不做施法、不做污染、不做配方。** 只有"元素会坏"这一件事。
但就这一件事，已经能玩出"仓储与节奏"的核心乐趣了。

### 2.1 载体：元素瓶

**新加一个设定**：元素不是"拿在手上的一块石头"，而是**装在瓶子里的东西**。

> 理由：① 给元素一个统一的载体，衰变才像是"瓶子里的东西在变质"；
> ② 光与暗的采集天然需要一个容器（折射棱镜 / 聚影瓶），有了统一载体就不突兀；
> ③ 让元素和"死寂物质"在视觉上明确分开 —— 前者是瓶装物，后者是固体建材。

| **空元素瓶** | `empty_vial` | 基础载体，也可当玻璃瓶用 |

## 三、衰变机制（本阶段的技术核心）

### 3.1 怎么实现"会坏"

**不存倒计时，只存诞生时刻，每次需要时现算。**

```
物品数据组件  elemental_verse:born_at = <诞生的游戏 tick>
当前阶段 = f(现在 tick − born_at, 环境修正, 容器修正)   ← 纯函数，随时算
```

**为什么必须这么做**（三个真问题一起解决）：

| 问题 | 为什么被解决 |
| --- | --- |
| 拆堆刷新计时（经典刷子漏洞） | 数据组件在拆分/合并时**原样复制**，诞生时刻跟着走 |
| 每次 tick 扫全背包（性能） | **不做 tick 扫描**。只在渲染、开容器、悬停时现算 |
| 箱子/区块没被加载时怎么办 | 因为算的是"当前时刻 − 诞生时刻"，**没加载的时间照样算进去** |

第三条特别重要：**离线也会坏**。你出门三天回来，箱子里的东西该坏就坏了。
这正是我们要的体验 —— 但也意味着**第一批实测时你会觉得"太快了"**，那是调参问题，不是 bug。

### 3.2 环境修正（本阶段做两条）

| 条件 | 修正 | 判定方式 |
| --- | --- | --- |
| **光**元素，所在位置亮度 ≤ 3 | **×2**（暗处加速） | 读物品所在方块的 `getMaxLocalRawBrightness` |
| **光**元素，所在位置亮度 ≥ 12 | **×0.5** | 同上 |
| **暗**元素，亮度 ≤ 3 | **×0.5** | 同上 |
| **暗**元素，亮度 ≥ 12 | **×2**（见光就散） | 同上 |
| **火**元素被用于合成 | **额外走 5 分钟** | 合成事件里扣除 |
| 水元素在瘴素区 | ×0.5 | **瘴素还没做，本阶段留空接口** |

> 注意：随身携带（在玩家背包里）时，亮度取**玩家所在位置**的亮度。
> 所以"晚上带着光元素赶路"是有代价的 —— 这个细节我觉得挺有味道。

### 3.3 衰变时长（本阶段初值，实测后调）

以**游戏日**为单位（1 游戏日 = 20 分钟）。

| 元素 | 阶段① | 阶段② | 总寿命 |
| --- | --- | --- | --- |
| 地 | 8 日 | 16 日 | **24 日** |
| 风 | 3 日 | 6 日 | 9 日 |
| 水 | 3.5 日 | 7.5 日 | **11 日** |
| 草 | 2.5 日 | 5 日 | 7.5 日 |
| 火 | 2 日 | 4 日 | 6 日 |
| 光 | 12 日 | 20 日 | **32 日** |
| 暗 | 12 日 | 20 日 | **32 日** |

> **一条要提醒你的**：这些数字在**实测时大概率会显得太快**。
> 属性测试时你会用 `/time add` 推时间，体感会被放大。
> 我建议**先按这张表做**，你实测完告诉我"地元素应该多久坏"，我再调 ——
> 这比我们现在凭空争论有用。

### 3.4 玩家看到什么

| 反馈 | 做法 |
| --- | --- |
| **物品名** | 阶段①的物品名加后缀，例如"土元素（浑）"；阶段②"土元素（浊）" |
| **Tooltip** | **模糊描述，不给数字**："尚有余韵 / 渐趋沉寂 / 行将死寂" |

## 四、本阶段的物品清单与获取方式

### 4.1 怎么拿到元素（本阶段不要配方）

**本阶段全部靠"与世界互动"，不做合成配方。** 理由是配方的材料链要等阶段 02 才有意义。

| 元素 | 获取方式 |
| --- | --- |
| **地** | 手持空瓶右键石头类方块（`#minecraft:base_stone_overworld` + 深板岩） |
| **水** | 手持空瓶右键水源方块 |
| **火** | 手持空瓶右键营火 / 岩浆（**岩浆会消耗瓶子，营火不会**） |
| **草** | 手持空瓶右键草方块 / 蕨类，**会把它变成泥土**（一次性） |
| **风** | 手持空瓶**在露天高处**（Y > 120）或**雷雨中**右键空气 |
| **光** | **需要折射棱镜**：白天下手持棱镜右键，得到光元素（瓶子留在手上） |
| **暗** | **需要聚影瓶**：亮度 ≤ 7 时手持聚影瓶右键，得到暗元素 |

**创造模式**：所有物品都进创造物品栏，方便测试。

### 4.2 本阶段要做的合成配方（只有三条）

| 配方 | 内容 |
| --- | --- |
| **空元素瓶** | 玻璃 ×2 + 任意死寂物质 ×1（让人一开始就能做瓶子） |
| **折射棱镜** | 玻璃 ×4 + 金元素 ×1（中期物，先用简单配方占位） |
| **聚影瓶** | 玻璃 ×4 + 影元素 ×1（同上，其实是个死循环 —— **这条要你拍板**，见第六节） |

### 5.2 【风险】图标三态的三种做法 —— 这条需要你知情

"亮 → 暗 → 灰"的三态图标有三种实现方式，代价差别很大：

| 做法 | 观感 | 风险 | 我的建议 |
| --- | --- | --- | --- |
| **A. 一条纹理到底** | 图标不变，只有名字与 tooltip 变 | **零风险** | 兜底方案 |
| **B. 注册三个物品，到点替换** | 图标会换 | 中。**致命缺陷：没被加载的物品不会 tick，离线不衰变**，要额外补一堆扫描逻辑 | 不采用 |
| **C. 一个物品 + 按阶段切换模型**（`range_dispatch` 读数据组件） | 图标会换，机制干净 | **我没法在这里验证**（无网络、无法编译） | **试，失败就退 A** |

**本阶段的做法**：先做 A 保证机制成立（**机制才是地基，图标是皮肤**），
然后**限时尝试 C**；如果 C 在半小时内没跑通，就把它挪到阶段 02 单独处理，
不阻塞本阶段的交付。

> 我偏向把"图标三态"当成一个独立的小任务，因为它属于**客户端渲染**，
> 和阶段 01 的"数据与机制"是两码事。混在一起会让这阶段的验收变模糊。

### 5.3 配置项（本阶段建的 `EVConfig`）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `decay.enabled` | true | 一键关掉衰变（调试用，也能给不喜欢这机制的服主） |
| `decay.globalMultiplier` | 1.0 | 全局衰变速度倍率，服主的手感旋钮 |
| `decay.lightDarknessMultiplier` | 2.0 | 光暗在明暗环境下的加速倍率 |
| `decay.hoverShowsExactTicks` | false | 调试用：tooltip 显示精确剩余时间 |
| `collection.requireContainerForLightShadow` | true | 光暗是否强制要容器 |

## 七、验收标准（阶段结束后你照着点）

编译成功后，进游戏（`dev.cmd runClient`）：

**基础**
- [ ] 创造模式物品栏里能看到 27 个物品 + 创造标签页
- [ ] 全部物品有中文名，悬停显示"尚有余韵"这类描述

**采集**
- [ ] 手持空瓶右键石头 → 得到土元素
- [ ] 手持空瓶右键水 → 得到水元素
- [ ] 手持空瓶右键营火 → 得到火元素，**瓶子没少**
- [ ] 手持空瓶右键岩浆 → 得到火元素，**瓶子少了一个**
- [ ] 手持空瓶右键草方块 → 得到草元素，**草方块变成泥土**
- [ ] Y > 120 露天右键空气 → 得到风元素
- [ ] 白天下手持折射棱镜右键 → 得到光元素，**棱镜还在**
- [ ] 手持空瓶在暗处右键 → **拿不到暗元素**（必须有聚影瓶）

**衰变（核心）**
- [ ] 把土元素放进箱子，`/time add 240000`（10 游戏日）→ 变成**砂元素**
- [ ] 再 `/time add 480000`（20 游戏日）→ 变成**死寂土**
- [ ] **死寂土不再变化**（放再久也是死寂土）
- [ ] 同一批土元素分两个箱子，一个放地上一个放**深度 60 的矿洞** → 都正常衰变（确认亮度不影响地）
- [ ] 光元素放**封闭暗室** vs 放**露天白天**，推同样时间 → **暗室里的明显先变**
- [ ] 暗元素反过来：**露天的明显先变**
- [ ] 把一摞 64 个拆成 32 + 32，**两摞状态完全一致**（防拆分刷新）
- [ ] 退出游戏、重启、推时间 → **衰变照常进行**（离线也算）

**死寂物质的用途**
- [ ] 死寂土能当方块摆出来（本阶段先给一个方块形态）

**配置**
- [ ] 配置里把 `decay.globalMultiplier` 改成 10 → 衰变明显变快
- [ ] 改成 0 或关掉 `decay.enabled` → 完全不衰变
