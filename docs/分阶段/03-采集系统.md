> 状态：**待你审**（第 1 版）

---

## 一、为什么是这一阶段

现在玩家能拿到的东西少得可怜：

| 能拿到 | 怎么拿 |
| --- | --- |
| 水元素 | 空瓶右键水源（唯一正经采集） |
| 霜元素 | 水元素衰变而来 |
| 死寂尘 | 走到尽头的产物 |

**其余全部只能在创造栏拿：** 地、风、火、草、**冰**、光、暗 —— 以及它们的衍生（砂/电/烬/木/晨/影）。

后果：

- **小包的冷却机制在生存里用不上**（没冰没霜来源，霜倒是有）
- **折射棱镜 / 聚影瓶是摆设**（拿不到光暗）
- 整个模组只剩"水 → 霜 → 尘"一条链

**本阶段的目标一句话：让生存模式的玩家能从世界里把七种元素和冰都采到。**

---

## 二、统一交互规则

所有采集都走同一套规则，玩家学一次就够：

1. 手持**对应的空容器**，右键目标
2. 容器里装上 **1 个**元素；**容器本身不消耗**
3. 容器里**已经有东西** → 右键无反应（不会覆盖）
4. **没有冷却、没有耐久、没有概率**（作者定：同原版水瓶）
5. 成功时：轻微音效 + 少量粒子 + 手臂摆动
6. 失败时**给出提示文字**（见第五节的"失败提示"）

> 第 6 条是我加的：光暗的失败条件（太亮/太暗）玩家看不见，不提示会以为坏了。

## 三、七种基础元素 + 冰：每一种去哪找

| 元素 | 载体 | 触发条件 | 细节 |
| --- | --- | --- | --- |
| **地** | 元素瓶 | 右键**石头类方块** | `#minecraft:base_stone_overworld` + 深板岩；方块**不变** |
| **水** | 元素瓶 | 右键**水源** | ✅ 已实现，保留 |
| **风** | 元素瓶 | **露天**（头顶无遮挡）且 **Y ≥ 120**，右键空气 | 高空才抓得到；雷雨中放宽到任意高度 |
| **火** | 元素瓶 | 右键**营火 / 火 / 岩浆** | 岩浆**消耗容器**（危险的采集），营火不消耗 |
| **草** | 元素瓶 | 右键**草方块 / 蕨 / 花** | 草方块**变成泥土**；花被摘下（一次性） |
| **冰** | 元素瓶 | 右键**冰 / 浮冰 / 蓝冰** | **现在这条给的是霜，要改成冰** |
| **光** | **折射棱镜** | **白天 + 露天 + 天空光 ≥ 12**，右键空气 | 洞里、夜里都拿不到 |
| **暗** | **聚影瓶** | 所在位置**方块亮度 ≤ 7**，右键空气 | 白天露天拿不到 |

### 3.1 关键改动：冰从"冰方块"来，霜只由衰变来

现在 `ElementVialItem.use` 里写着：

```java
ElementType collected = state.is(BlockTags.ICE) ? ElementType.FROST : ElementType.WATER;
```

意思是"对冰方块用 → 得到霜"。**这条要反过来**：对冰方块 → 得到**冰**。
霜的唯一天然来源是"水元素衰变"，这样两者才各归其位：

```
水 ──衰变──▶ 霜（基础冷却剂，随手可得）
冰 ──右键冰方块──▶ 冰（高级冷却剂，得去找冰原）
```

### 3.2 衍生元素：全部由衰变产生，不做采集

| 衍生 | 来源 |
| --- | --- |
| 砂 / 电 / 烬 / 木 / 晨 / 影 | 对应稳定元素衰变（已有） |
| **霜** | 水衰变（已有） |
| **冰** | **采集**（见 3.1），且**不衰变**（它是材料） |
| 金 / 芽 | **本阶段不产出**（留给以后：金→精密合成载体，芽→净化起点） |

## 四、失败提示

采集失败时在动作栏（`above hotbar`）给一句人话，而不是静默。

| 场景 | 提示 |
| --- | --- |
| 拿光元素但太暗/夜里 | 「这里没有光可捉」 |
| 拿暗元素但太亮 | 「这里太亮了，抓不住影」 |
| 拿风元素但头顶有遮挡 | 「风进不来」 |
| 拿风元素但高度不够 | 「风太弱了，再高点」 |
| 容器已经装着东西 | 「先把它用掉」（或干脆不响应，见待拍板） |

## 五、实现方案

### 5.1 代码结构

```
element/
├── ElementCarrier.java        + 每种载体「能采什么」的入口
├── gathering/
│   ├── GatheringRule.java     （新）一条采集规则的接口：match(level, pos, player) + 产出
│   ├── BlockGathering.java    （新）按方块/方块标签采集（地/水/火/草/冰）
│   ├── AirGathering.java      （新）按环境采集空气（风/光/暗）
│   └── GatheringHooks.java    （新）把上面这些接到物品的 use()
└── ElementVialItem.java       按 carrier() 分派到具体规则
```

**为什么不直接写一堆 if**：七种元素的判定条件差别很大（方块 / 空气 / 亮度 / 高度 / 天气），
以后还要加（金、芽）。做成"规则列表"，加一条就是加一个类，不改主流程。

### 5.2 判定细节（避免玄学）

| 判定 | 用什么 |
| --- | --- |
| 露天 | `level.canSeeSky(pos.above())` |
| 天空光 | `level.getBrightness(LightLayer.SKY, pos)` ≥ 12 |
| 方块亮度 | `level.getMaxLocalRawBrightness(pos)` ≤ 7 |
| 高度 | `pos.getY() >= 120` |
| 雷雨 | `level.isThundering()` |
| 石头类 | `#minecraft:base_stone_overworld`、`#minecraft:deepslate_ore_replaceables`、`Blocks.DEEPSLATE` |
| 冰类 | `BlockTags.ICE` |
| 草类 | `Blocks.GRASS_BLOCK`、`Blocks.FERN`、`#minecraft:flowers`、`#minecraft:small_flowers` |

### 5.3 顺带要修的

- 采集成功后**不要触发方块破坏**（`InteractionResult.SUCCESS` 而不是 `CONSUME`）
- 草方块变泥土用 `level.setBlockAndUpdate`，只在服务端做
- 元素瓶上已有的"右键水"逻辑要迁到新规则里，**不能留两份**

| # | 问题 | 我的建议 |

| **1** | **火元素：岩浆要不要消耗容器？** | **要**（岩浆是危险采集，和营火拉开差距）。但这会让玩家掉瓶子，可能烦 —— 你觉得呢 |

## 七、验收标准

**这一阶段必须能"从零开始玩"** —— 所以验收方式就是开一局生存，不用创造栏：

- [ ] 空手做一个元素瓶（玻璃瓶 ×1），**右键石头** → 土元素
- [ ] 右键水 → 水元素（原有功能不回归）
- [ ] 右键**草方块** → 草元素，**草方块变成泥土**
- [ ] 右键营火 → 火元素，**瓶子没少**
- [ ] 右键岩浆 → 火元素，**瓶子少一个**（若第 1 条选"消耗"）
- [ ] 爬到 **Y ≥ 120 露天**右键空气 → 风元素；在洞里右键 → **提示"风进不来"**
- [ ] 找到**冰原**，右键冰方块 → **冰元素**（不是霜）
- [ ] 做**折射棱镜**，白天露天右键 → 光元素；**在洞里右键 → 提示"这里没有光可捉"**
- [ ] 做**聚影瓶**，亮度 ≤ 7 右键 → 暗元素；**白天露天右键 → 提示"这里太亮了"**
- [ ] 全程**不需要开创造栏**
