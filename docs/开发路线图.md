## 一、协作流程（每一步都按这个走）

你要求的是"**每次开启新内容之前，先修订小策划案**"。所以固化成一个循环：

```
┌─ 1. 我起草「分阶段/NN-xxx.md」小策划案 ─────────────┐
│     内容：本阶段的目标 / flag 清单 / 具体数值 /       │
│           实现方案 / 验收标准 / 需要你拍板的点        │
│                        ↓                            │
│ 2. 你读、你改（直接改文件，或告诉我怎么改）           │
│                        ↓                            │
│ 3. 我们确认「待拍板」全部有答案 → 冻结这一版          │
│                        ↓                            │
│ 4. 我按冻结版写代码                                  │
│                        ↓                            │
│ 5. 验收：CI 编译结果 + 给你的本地实测清单             │
│                        ↓                            │
│ 6. 你进游戏实测 → 反馈 → 修（回到 4，不回到 1）        │
└─────────────────────────────────────────────────────┘
```

**铁律**：
- **第 3 步没过，我不动代码。** 不"顺手先写一点"。
- 一次只开一个阶段。**开工前必须先有那一份小策划案。**
- 数值改动**先改小策划案**，再改代码 —— 不然文档和代码会分家。
- 每个阶段的产物 = **可进游戏看到、能玩一下**的东西。不做"纯内部重构阶段"。

## 三、各阶段详细拆解

### 阶段 01 · 项目地基 + 衰变系统

**小策划案**：`分阶段/01-项目地基与衰变.md`

**目标**：把模板变成我们的仓库，并且让"元素会坏"这件事成立。

**要做的（flag 清单）**：
- 清掉模板占位（`example_block` / `example_item` / `Config` 的示例项）
- 包结构立起来：`registry/`（集中注册）、`element/`（元素与衰变）
- **7 种稳定元素**物品 + **10 种衍生元素**物品 + **7 种死寂物质**物品
- **衰变核心**：`born_at` 数据组件 + 纯函数判定当前阶段（见总纲 2.5）
- **图标三态**（亮/暗/灰）与**模糊 tooltip**（"尚有余韵 / 渐趋沉寂 / 行将死寂"）
- **环境修正**：光（暗处加速）、暗（亮处加速）、水（瘴素区加速）—— 瘴素还没做，先留接口
- **采集途径**：地（挖石）、水（取水）、火（岩浆/营火）、草（植被）、风（高处/雷雨）
- **光暗的采集容器**：折射棱镜 / 聚影瓶（这是光暗的入场门槛）
- **创造模式物品栏**一个，中英文 lang 文件建好
- `dev.cmd`（一键编译/启动，自动接 JDK 与工作区内的 Gradle 缓存）
- `README.md` 重写（中文，说清这是什么、怎么编译、怎么玩）
- git 初始化 + CI 打通

**验收标准（我会给你一份逐条实测清单）**：
1. `gradlew build` 通过，产出 jar
2. 进游戏，创造模式里能看到全部元素物品
3. 把地元素放普通箱子里，用指令把游戏时间推快，**看到它变成砂、再变成死寂土**
4. 把光元素放暗处 vs 放亮处，**推进同样的时间，暗处的明显先变**
5. 悬停显示的是"渐趋沉寂"这类描述，**不是数字**
6. 死寂土能当建材摆出来

**需要你拍板的点**：
- 七元素与十衍生元素的**中英文名字**（现在是我起的，你可能有更贴合设定的叫法）
- 衰变时长表（总纲 2.3）**第一版手感**——这个必须实测后调
- 光暗的采集容器叫"折射棱镜 / 聚影瓶"合不合适

### 阶段 02 · 特殊容器 + 仓储分级

**小策划案**：`分阶段/02-特殊容器与仓储分级.md`
**目标**：让玩家第一次能**干预**衰变；同时把光/暗从"换个贴图的元素瓶"变成真正的另一种容器。
**要点**：光/暗独立物品（折射棱镜 / 聚影瓶）+ 石制密封仓 + 冰的冷链 + **容器内也会衰变**（阶段 01 的空档）。
**顺延**：符文柜 → 后续阶段（需要整套"供能"概念）。

**验收标准**：
1. 同一批地元素，分放地上 / 石仓 / 符文柜，**推进同样时间，三者状态明显不同**
2. 符文柜元素槽空了以后，**里面的东西开始正常速度衰变**（不是毁掉）
3. 把一摞元素拆成两摞，**两摞的衰变进度完全一致**（没被刷新）
4. 冰窖里的元素比外面慢

**需要你拍板**：符文柜吃元素的速率（1/游戏日是不是太贵或太便宜）；符文柜的合成难度。

### 阶段 03 · 采集系统

**状态：✅ 已实现并验证。**

让生存玩家能从世界里采到全部七种元素 + 冰，每种都留好"在家量产"的路（总纲 12.1）。

- 地：从**矿物**取，按稀有度给 1 / 2 / 3 份
- 水：右键水源
- 风：露天 + Y≥120（雷雨不限高度）
- 火：岩浆（扣血、一次 5 份）/ 火焰方块（灭火）/ 烈焰粉 + 空瓶（可再生基线）
- 草：草方块 → 泥土（会再长回来）、蕨与花被采掉
- 冰：冰方块 → 冰；蓝冰 ×9 → 浮冰 ×9 → 冰 ×3 → 消失
- 木：树苗 / 枯木 / 树叶；原木 ×5 → 去皮木（不再产出）
- 光 / 暗：折射棱镜 / 聚影瓶 + 光照条件
- 营火 → 烬，能采 5 次后熄灭

**小策划案**：`分阶段/03-采集系统.md`

### 阶段 04 · 仪式台与申明板（元素值框架）

> **术语澄清**：申明板 ≠ 符文版，也 ≠ 符文板。申明板是总纲第五章的模组核心。

**这一阶段的真正产物是一套数值语言，而不是一个玩法。**

```
元素值（火/水/地/风/草/光 六轴 + 暗=负光）
   ↓
申明板（把元素值写成一条申明）
   ↓
仪式台（定义模式：写入） / 已定义申明板（引用模式：直接释放 或 当锻造模板）
```

- **元素值框架（底层重写）**：`ElementValue` 六维向量；强度 = L1 范数；
  施法消耗 = ⌈强度⌉ 个同元素容器（霜 1.5 → 2 个霜瓶）
- **仪式台**：三投入口，**本期只有第一口生效**（1/3/9 个 → 元素值 1/2/3，27 个质变留后续）；
  紧挨密封舱/符文柜时，可直接从容器里选最多 9 种、取 3 种，且此时禁用背包与元素小包
- **申明板**：直接释放 + 当锻造模板；本期**只做剑**
- **余热**：只引概念（存区块，06 阶段瘴素再读）
- **符文柜**：只能吃**霜/冰**的申明；冰/霜元素值越高维持越久

**小策划案**：`分阶段/04-仪式台与申明板.md`

### 阶段 05 · 申明板深化：形态 / 附属 / 时序 / 跑偏

**目标**：让"可写的法术"真正成立，并让"模糊的申明"有代价。

**要做的**：
- **形态字段**：自身 / 发射 / 交互 —— 同一个组合变成完全不同的法术（总纲 5.3）
- **附属材料**十种（总纲 5.4）：稳定 / 延时 / 延长 / 相位 / 急速 / 冷凝 / 净化 / 隐匿 / 催生 / 中和
- **时序字段**：即时 / 延时 N / 持续 N
- **偏差系统**：偏差率公式 + **四种跑偏表现**（目标/形态/量级/时序）
- **跑偏的余热 ×1.5**
- **知识解锁**：先做成调试指令可解锁（残卷留到 06 阶段），用于测试各字段
- 申明板可以被**读回**（右键看到它写了什么）

**验收标准**：
1. 同一个"火 + 释放"，切换三个形态**得到三种完全不同的结果**
2. 故意留空 → **能看到跑偏**（打到自己、原地爆、吃掉 3 倍元素、当场就炸）
3. 加上"稳定"附属后，**跑偏率明显下降**
4. 时序设为"延时 5 秒"，**确实是 5 秒后才生效**
5. 跑偏的那一次，**余热比正常那一次高**

**需要你拍板**：偏差率公式的手感（现在 15%/字段，上限 90%）；四种跑偏的表现够不够"有意思"。

### 阶段 06 · 瘴素三阶 + 浊化 + 方碑

**目标**：把 03/04 埋下的余热变成**玩家能看见、能感受的压力**，并给出第一层手段。

**要做的**：
- **区块污染值**：从余热 + 衰减中元素量 + 邻块扩散结算（总纲 3.4）
- **三阶可视化**：灰绿薄雾、粒子、雾的颜色与浓度随阶变化（客户端渲染）
- **浊化系统**：0/1/2/3 层，效果按总纲 3.2；累积与消退
- **HUD 与屏幕效果**：边缘脏渍（三层递进）+ 第三层呼吸式暗角。**不显示数字**
- **灼喉砂**：三种形式（块 / 沉积 / 气团）+ 走过加速浊化 + 砂中和
- **面部位装备槽**（自建简槽）+ 三件防护（−25% / −40% / −60%，上限 −85%）
- **元素方碑**：底座 + 可放置的碑 + 纯净元素核心（会衰变，约 5 游戏日耗尽）
- **净化仪式**：芽 ×4 + 元素 ×16 + 中和块，分轮推进

**验收标准**：
1. 在原地连续施法，**肉眼看到区域慢慢变灰绿**
2. 在侵蚀区待 20 分钟以上，**屏幕边缘脏渍出现 → 挖掘变慢 → 视野起雾**
3. 走出来，**浊化慢慢退掉**
4. 戴上三件套，**同样的时间只叠到一半**
5. 放下方碑，**范围内污染值只降不升**；核心耗尽后**失效**
6. 跑一轮净化仪式，**污染阶数明显退了一档**

**需要你拍板**：三阶阈值与浊化数值的**手感**（这是最影响体验的一项，宁可偏轻）；
面部位槽用自建还是软依赖 curios。

### 阶段 07 · 群系与生态

**目标**：让污染**长在地图上**，并且给玩家知识来源。

**要做的**：
- **四个群系**：瘴素侵蚀区 / 死寂地带 / 晶化领域 / 灾变前遗迹
- **动态边界**：群系边界跟随玩家造成的污染值扩张（**方案待定，见技术备忘 T6**）
- **地表装饰**：灼喉砂、死寂土壤、枯败植被、晶簇
- **蚀化生物**：复用原版生物渲染 + 灰绿发光/破损叠加
- **灾变前遗迹结构**：残垣、符文、破碎装置
- **残卷**：解锁申明板字段的正式途径（替换 04 阶段的调试指令）
- 群系音效与音乐（可选，能省则省）

**验收标准**：
1. 能用传送指令进到每个群系，**看/听得出来是四个地方**
2. 在侵蚀区持续施法，**一段时间后群系边界真的往外推了**
3. 遗迹里能捡到残卷，**用它解锁一个新字段**
4. 蚀化生物会刷，行为"错乱、无目的"

**需要你拍板**：动态边界的实现方案（性能与观感的取舍）；群系的视觉基调。

### 阶段 08 · 晶裔（最大的一块）

**目标**：邻居搬来了。

**要做的**：
- **晶裔实体**：基础 AI（观察、后撤、交易、反击）
- **好感度**：每玩家每聚落连续值 + 变动表（总纲 4.2）
- **水晶音效四态**：清脆 / 嗡鸣 / 不和谐双音 / 碎裂
- **四态行为**：共鸣 / 避战 / 排斥 / 敌视
- **记住并复用你的法术**：记录玩家最近一次施法组合，反击时复用
- **交易界面**：以申明板为货币，回报按价值公式
- **晶裔材料四件**：晶核 / 相晶 / 和鸣晶 / 知识晶
- **晶脉网络**：结晶方块、晶脉结节、扩张逻辑
- **晶体首领**：击败 → 聚落转入避战
- **核心与再生**：完全消灭的代价与再生概率
- **知识晶**：存储 / 复制一块申明（法术卷轴）

**验收标准**：
1. 靠近晶裔，**听到的是嗡鸣不是敌意音效**，它不打你
2. 送一块它没见过的申明 → **好感上升，音效变清脆**，能交易
3. 在它核心附近狂施法 → **好感掉到排斥**，它反击，**而且用我刚用的招打我**
4. 打死晶体首领 → **聚落进入避战，让出土地，我能开采**
5. 把核心也毁掉 → **过一段时间别处重新生成**，相晶/和鸣晶**变难拿**

**需要你拍板**：兑换比率；晶裔的外观方向（这是模组的脸面，值得多花时间）；
"学法术"的表现形式（是原样反弹还是变形后打回来）。

### 阶段 09 · 神器四件

**目标**：让玩家能"从忍翻成赢"。

**要做的**：
- **永痕之花**：无限储能池 + 与方碑网络联动
- **冷月**：切断晶脉局部连接 → 人工造出避战态
- **呼啸之心**：移动净化场
- **原初之焰**：献祭换一次无视规则的效果
- 四件各自的**稀有材料获取链**（不能是简单的合成表）

**验收标准**：
1. 用永痕之花供能的方碑，**不再需要换核心，永久安全区成立**
2. 用冷月切断一片晶脉，**那一块的晶裔确实"听不见"了**
3. 带着呼啸之心移动，**净化场跟着走**
4. 原初之焰的献祭**有明确代价**，且效果确实"无视规则"

**需要你拍板**：四件的获取难度曲线；原初之焰的代价具体是什么（等级？生命上限？物品？）。

## 四、技术备忘（可能被推翻的决策，先记着）

| # | 事项 | 决策 | 理由 |
| --- | --- | --- | --- |
| **T1** | 衰变的存储方式 | **不存倒计时，只存 `born_at` 时刻，现算** | 防拆分刷新、免 tick 扫描、存档小（总纲 2.5） |
| **T2** | 元素三态的物品实现 | **一个物品 + 数据组件 + 动态纹理/名称**，不是三个物品 | 拆分合并天然安全；但需要动态模型（`ItemProperties` / 自定义 `BakedModel`），阶段 01 要验证可行性 |
| **T3** | 区块污染值存哪 | NeoForge **`AttachmentType` 挂区块**（codec 序列化） | 比自建 SavedData 更贴框架，卸载重载不丢 |
| **T4** | 污染值同步到客户端 | NeoForge **`CustomPacketPayload` + PayloadRegistrar**，只同步玩家附近的区块 | 1.21 的网络 API 已是这个写法 |
| **T5** | 面部位装备槽 | **自建简化槽**（先），curios 软依赖（后，如果玩家要求） | 不背一个可选依赖；我们的需求只是"一个额外的面部位" |
| **T6** | 群系动态边界 | **待定**：方案 A = 注册固定群系 + 用装饰/覆盖层表现污染；方案 B = 自建群系源读污染值动态出群系 | A 稳、性能好，但边界"跳"；B 观感好，但要走 `ChunkGenerator` 的群系源，风险高。**阶段 07 前定** |
| **T7** | 蚀化生物 | **复用原版生物 + 渲染层叠加**，不做新模型 | 省预算给晶裔 |
| **T8** | 施法的执行方式 | **数据驱动的"法术描述对象"**（元素/操作/形态/量级/附属/时序 → 一个可执行效果） | 六字段组合爆炸，硬编码写不完 |
| **T9** | 翻译 | 从第一天就写 `zh_cn.json` + `en_us.json` 两份 | 补翻译是最容易被欠下的债 |
| **T10** | 目标 MC 版本 | **1.21.1 锁死**，中期不跟版本 | 1.21.1 是当前生态最稳的 NeoForge 版本 |
