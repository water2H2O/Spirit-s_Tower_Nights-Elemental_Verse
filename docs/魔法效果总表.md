## 一、一次施法的完整数据流

```
仪式台三口                     申明板                    施法
──────────────────────────────────────────────────────────────
① 主料 ─┐
② 辅料 ─┼─▶ inputValue() ──▶ 匹配反应 ──▶ 现象 ──▶ 按形态分派
        │   （主料+辅料）      （至少包含）
③ 态   ─┴─▶ SpellParams（不进入 inputValue）──▶ 六参数
                │
                └─▶ 写入时把魔法名存进板子（客户端没有反应表）
```

| 环节 | 类 | 说明 |
| --- | --- | --- |
| 投入 | `RitualAltarBlockEntity` | 三口 × 每口 1/3/9 个 → 档 1/2/3 |
| 申明 | `Declaration` | 主料 + 辅料 + 态 + 魔法名 |
| 匹配 | `ReactionManager.match` | **至少包含**，取要求最多的那条 |
| 现象 | `Phenomenon` | type / element / amount / duration / cost |
| 参数 | `SpellParams` | 烈度 / 范围 / 持续 / 造拆 / 连锁 / 极性 |
| 分派 | `SpellCaster` | 按 `form` 走触摸 / 自生 / 弹射物 |

## 二、三种触发形态

| 形态 | 现状 | 行为 | 备注 |
| --- | --- | --- | --- |
| **触摸**（touch） | ✅ **已实现** | 射线 6 格，命中方块/实体 | 申明板与武器**默认**都是这个 |
| **自生**（self） | ✅ **已实现（基础）** | 现象直接落在施法者身上，不做射线 | 火焰保护这类增益就该用它 |
| **弹射物**（projectile） | ⏳ **结构已留，未实现** | 应发射一个投射物，命中后生效 | 需要：投射物实体 + 渲染 + 命中回调 |

> 现在新写的板子 `form` 记录为 `touch`；
> 旧板子上写的是 `projectile`，会**按触摸跑**（不会报错，只是没有飞行物）。

## 三、基础与代表魔法（完整 29 条见第四节）

> 完整反应表在 `src/main/resources/data/elemental_verse/reaction/*.json`。
> 下面只列最早跑通的基础链路，不代表总数。

| 魔法 | 消耗（至少） | 现象 | 实际效果 | 形态 |
| --- | --- | --- | --- | --- |
| **点燃** | 火 ≥1 | `ignite` | 命中处着火；实体则着火 tick | touch |
| **灭火** | 水 ≥1 | `douse` | 清掉命中点附近 2 格内的火 | touch |
| **燃烧** | 火 ≥1 + 草 ≥1 | `sustained_element_damage` | 对实体造成火伤 + 着火 | touch |
| **蒸汽** | 火 ≥1 + 水 ≥1 | `steam` | 小伤害 + 击退 | touch |
| **熔岩** | 火 ≥1 + 地 ≥1 | `lava` | 命中面放岩浆；实体则着火 + 减速 | touch |
| **火焰保护** | 火 ≥1 + 光 ≥1 | `fire_resistance` | 给自己抗火 | touch（适合 self） |

**这些现象都会吃态参数**：点燃吃「烈度 × 持续」定着火时长、吃「范围」定点燃面积；灭火吃「范围」；伤害吃「烈度」。

## 五、双板拼接（作者提出，待设计）

> **拼接 = 两块申明板 + 一种驱动材料 + 一种修饰元素。**

| 角色 | 谁 | 作用 | 类比 |
| --- | --- | --- | --- |
| 主体 | 申明板 A | 决定基础魔法 | 函数体 |
| 主体 | 申明板 B | 决定另一段魔法 | 函数体 |
| **驱动** | 一种材料 | 让两块板能拼起来（消耗品） | 运算符 |
| **修饰** | 一种元素 | 修改拼接后的结果 | **形参** ← 作者原话 |

### 为什么修饰元素就是"形参"

它和三投入口里的**态**是同一个东西 —— 都是"用一个元素去改参数"。
所以**直接复用第六节的六轴参数表**，不需要新的表：

| 修饰元素 | 改什么 |
| --- | --- |
| 火 | 烈度 |
| 风 | 范围 |
| 光 | 持续 |
| 地 | 造/拆 |
| 水 | 连锁 |
| 草 | 极性 |

### 还需要定的三件事

| # | 问题 | 我的建议 |

| 1 | 拼接后的效果是**依次执行**还是**合并**？ | 依次执行（A 完了 B 再上），实现简单、可预测 |

## 七、元素权重表（2026-10-18 平衡后，唯一口径）

> **平衡原则（作者定）**：所有元素的强度压在 **1.0 ~ 2.5** 之间，
> 不允许任何一个"元素值特别高"。

### 基础元素

| 元素 | 元素值 | 强度 | 主成分 |
| --- | --- | --- | --- |
| 火 / 水 / 地 / 风 / 草 / 光 | 单轴 1.0 | **1.0** | 对应轴 + |
| 暗 | `{光:-1}` | **1.0** | 光 − |

### 二级元素

| 元素 | 元素值 | 强度 | 主成分 | 备注 |
| --- | --- | --- | --- | --- |
| 霜 | `{水:1, 火:-0.5}` | **1.5** | 水 + | 作者原定 |
| 烬 | `{火:1, 光:-0.5}` | **1.5** | 火 + | |
| 砂 | `{地:1, 水:-0.5}` | **1.5** | 地 + | |
| 芽 | `{草:1, 水:+0.5}` | **1.5** | 草 + | |
| 电 | `{风:1.5, 光:0.5}` | **2.0** | 风 + | |
| 晨 | `{光:1.5, 火:0.5}` | **2.0** | 光 + | |
| 影 | `{光:-1.5, 草:-0.5}` | **2.0** | 光 − | 负向也有强弱 |
| 木 | `{草:2}` | **2.0** | 草 + | 纯强化 |
| 冰 | `{水:1.5, 火:-1}` | **2.5** | **水 +** | 解决并列（原 1 vs -1 被判成负火） |
| 金 | `{地:2, 火:0.5}` | **2.5** | 地 + | 原 3.0 过高，已压到 2.5 |

### 三条设计约束（以后加元素也要守）

1. **强度上限 2.5**：否则"堆一个元素"就成唯一最优解
2. **避免并列**：主分量的绝对值必须**严格大于**任何修饰分量
   （冰原来是 `1 vs -1` 并列，结果由裁决顺序决定 —— 反直觉）
3. **负值是稀缺资源**：只有少数元素带负分量，正负才有意义
